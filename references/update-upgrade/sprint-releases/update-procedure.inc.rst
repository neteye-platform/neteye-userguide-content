
If Sprint Releases are enabled, the upgrade procedure is the same as the standard upgrade procedure.
Given the intended use of Sprint Releases, |ne| updates should be less frequent in favor of Sprint Releases
upgrades. For this reason, only OS-related packages will be updated in the current Sprint Release, while
NetEye-related bugs will be fixed in the next Sprint Release.

To update a |ne| instance with Sprint Releases enabled, you can follow the traditional :ref:`update-procedure`.
