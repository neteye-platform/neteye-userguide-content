Visualize Alyvix Performance Metrics in Elastic Observability
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

As a user, I want to be able to collect, explore and understand data on the Test Cases
performance metrics sent by an Alyvix Session to the Elastic Stack, so
that I can analyze the Test Cases performance based on the collected metrics data.

This guide will explain how to configure Alyvix nodes to send performance metrics to the Elastic APM server
using the `OpenTelemetry (OTEL) protocol <https://opentelemetry.io/>`_, and how to visualize these metrics in the
Elastic Observability UI.

Prerequisites
`````````````

In order to be able to collect the performance metrics generated by your Alyvix node in |ne|,
the following prerequisites must be met:

- The Alyvix node must be updated to Alyvix Service version 2.7.2 or later.

- The :ref:`neteye-alyvix <alyvix-overview>` and the :ref:`neteye-elastic-stack <elastic-feature-module>` modules must be installed in the |ne| system and enabled
  for the |ne| Tenants to which the metrics belong to.
  Please refer to the :ref:`neteye-components` for installing additional |ne| modules and to the
  :ref:`neteye-tenant-config-modify` or the :ref:`neteye-tenant-config-create`
  section to enable the module for an already existing Tenant or to create a Tenant and directly enable the module for it.
- The Alyvix node should be reachable by the |ne| Master.

  .. note::

    If the Alyvix node is a :ref:`alyvix-multitenant-tenant-specific-node` or a :ref:`alyvix-single-tenant-via-satellite-node`,
    and the Alyvix node cannot be reached directly by the |ne| Master, then the OTEL configuration should be done manually
    on the Alyvix node. To perform the configuration of such Alyvix nodes, you can follow the dedicated section
    about how to :ref:`alyvix_node_manual_otel_configuration`.

- The TCP port 8200 of the |ne| Master or the |ne| Satellite, depending on the
  :ref:`architecture of the Alyvix node <alyvix-nodes-architectures>`, should be reachable by the Alyvix node.

- If the Alyvix node is connected to a |ne| Satellite, the Elastic APM Server should be installed and
  configured on the |ne| Satellite.

Step 1. Put a Test Case in Production
`````````````````````````````````````

First of all, ensure Alyvix is set to generate the metrics that you would like to collect,
:ref:`putting a Test Case in production <alyvix-put-test-case-in-production>`.


Step 2. Configure the Alyvix Node
`````````````````````````````````

After having configured a Test Case to generate metrics, the OTEL connection between the
Alyvix node and the Elastic APM server must be configured.

- Use the :ref:`neteye-alyvix-node-setup` command to automatically configure the OTEL connection
  between the Alyvix node and the |ne| Master or the |ne| Satellite, depending on the
  :ref:`architecture of the Alyvix node <alyvix-nodes-architectures>`. The command will automatically
  configure the Alyvix node to send the metrics to the APM Server running on the |ne| Master or on the |ne| Satellite.
  The command will take care of creating the necessary authentication credentials for the Alyvix node
  on the APM server related to every tenant that is using the Alyvix node.

.. _view-metrics:

Step 3. Enjoy your metrics
``````````````````````````

Metrics generated during the run of Alyvix Session will be automatically collected by the APM server
running on the Elastic Agent of the |ne| Master or the |ne| Satellite and stored in Elasticsearch.
You can then visualize the collected metrics in the Elastic Observability UI by navigating to
:menuselection:`Observability --> Applications` in the Kibana web interface. You will find all the
Alyvix Test Cases metrics under the 'Alyvix' Service.


.. _alyvix_node_manual_otel_configuration:

Configure the Alyvix Node Manually
``````````````````````````````````

If the Alyvix node is connected to a |ne| Satellite and is not reachable by the |ne| Master, the :command:`neteye alyvix-node setup` command
fails since it cannot reach the Alyvix node and thus it cannot configure the OTEL connection. In this case, you can
configure the OTEL connection manually on the Alyvix node by following these steps:

#. On the |ne| Master, run the following command to generate the OTEL configuration payload to be used on the Alyvix node:

   .. code-block:: console

      neteye alyvix-node print-otel-configuration --node-name NODE_NAME --tenant-name TENANT_NAME

   Replace ``NODE_NAME`` with the hostname of the Alyvix node and ``TENANT_NAME`` with the name of the Tenant.
   This command will generate the OTEL configuration payload and the authentication credentials for the Alyvix node to
   send the metrics to the |ne| Satellite belonging to the specified Tenant and it will save the payload in a file
   in the :file:`/tmp` directory, named :file:`otel_config_<tenant_name>_<node_name>.json`.

#. On the |ne| Satellite, or any host that can reach the Alyvix node, send the generated OTEL configuration payload
   to the Alyvix node by running the following command:

   .. code-block:: console

      curl -X POST https://<ALYVIX_NODE_IP>/v5/super-admin/otel \
      -H "Content-Type: application/json" -H "Authorization: Bearer <JWT_TOKEN>" \
      -d @<OTEL_CONFIGURATION_PAYLOAD_FILE>

   Where:
    - ``<ALYVIX_NODE_IP>`` is the IP address of the Alyvix node.
    - ``<JWT_TOKEN>`` is the JWT token needed to authenticate on the Alyvix node. The JWT can be generated by running the
      :command:`icingacli neteye jwt create` command on the Icingaweb2 active node on the |ne| Master.
    - ``<OTEL_CONFIGURATION_PAYLOAD_FILE>`` is the OTEL configuration payload file generated by the :command:`neteye alyvix-node print-otel-configuration` command.

#. Once the OTEL configuration payload is sent to the Alyvix node, the Alyvix node should be able to send the metrics to the
   APM server running on the |ne| Satellite using the port 8200.
