.. _neteye-tenants-configuration:

This section will explain how you can configure the |ne| Tenants that are part of your infrastructure.

|ne| ships a default ``master`` Tenant which is defined even in case no Tenants are used. All the data
generated by the |ne| Master belong to this Tenant.

You can create additional |ne| Tenants with the following command:

.. code:: bash

   neteye# neteye tenant config create <tenant_name> --display-name "Tenant Name"

The ``--display-name`` is a mandatory option of the tenant creation command and specifies a user-friendly
representation of the <tenant_name>.

For other command options and advanced usage, including the modification of existing |ne| Tenants,
please refer to :ref:`neteye-tenant`.

For every newly created Tenant a new role will appear in the Roles section of
the |ne| Access Control. By default a new role automatically acquires the title
following the syntax: ``neteye_tenant_<tenant_name>``, and inherits Module permission
settings of the Tenant it was created for.

.. note::
   It is important to remember that this role should not be altered.
   In order to assign a user to the tenant, first create a new role that inherits
   the properties of the tenant role, set necessary permissions and then assign
   this role to the user.
