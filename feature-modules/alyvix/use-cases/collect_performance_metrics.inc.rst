Visualize Alyvix Performance Metrics
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

As a user, I want to be able to collect, explore and understand data on the Test Cases
performance metrics sent by an Alyvix Session to an InfluxDB, so
that I can analyze the test case performance based on the collected metrics data.

Prerequisites
`````````````

In order to be able to collect the performance metrics generated by your Alyvix node in |ne|,
the ``neteye-alyvix`` module must be enabled for the |ne| Tenants to which the metrics belong to.

To enable the module for an already existing Tenant, please refer to the :ref:`neteye-tenant-config-modify`.
section.

To create a Tenant and directly enable the module for it, please refer to the :ref:`neteye-tenant-config-create`
section.

Step 1. Put a Test Case in Production
`````````````````````````````````````

First of all, ensure Alyvix is set to generate the metrics that you would like to collect,
:ref:`putting a Test Case in production <alyvix-put-test-case-in-production>`.

.. _visualize-alyvix-performance-metrics-configure-the-alyvix-node:

Step 2. Configure the Alyvix Node
`````````````````````````````````

After having configured a Test Case to generate metrics, the connection between the
Alyvix node and |ne| must be configured. The configuration procedure depends on the
:ref:`architecture of the Alyvix node <alyvix-nodes-architectures>`.
The node can belong to one of the following types:

- :ref:`alyvix-multitenant-tenant-specific-node`
- :ref:`alyvix-single-tenant-via-satellite-node`
- :ref:`alyvix-multitenant-tenant-shared-node`
- :ref:`alyvix-single-tenant-direct-to-master-node`

Please make sure to follow the steps related to the architecture of your Alyvix node.

**Multitenant - Tenant Specific or Single Tenant - Via Satellite**

Run the following command on the Satellite to which the Alyvix node is connected,
which will configure Alyvix to send metrics to the Satellite via a NATS channel:

  .. code:: bash

    curl -H 'Content-Type: application/json' -H 'Authorization: Bearer <jwt_token>' \
      -X POST -d '{
          "tenant_name": "<tenant_name>",
          "nats_ca": "<nats_ca>",
          "nats_cert": "<nats_cert>",
          "nats_key": "<nats_key>",
          "nats_subject_name": "alyvix.metrics",
          "nats_ip_port": 4222
        }' \
      'https://<alyvix_node_hostname>/v5/super-admin/nats-influxdb'

  where:

  - ``jwt_token`` is a JWT token to authenticate the request, which can be generated on the **NetEye Master** with the command :command:`icingacli neteye jwt create`. Note that the JWT token is short-lived, so make sure to generate it right before executing the command and to use it within its validity period.
  - ``tenant_name`` is the name of the Tenant to which the Alyvix node (and the Salellite) belongs to. The exact name can be retrieved by running, on the **NetEye Master**, the :command:`neteye tenant list` command.
  - ``nats_ca`` is the content of the file that can be found on the Satellite in the file :file:`/root/security/ca/root-ca.crt`.
  - ``nats_cert`` is the content of the file that can be found on the Satellite in the file :file:`/neteye/shared/nats-server/conf/certs/<tenant_name>-alyvix_metrics.crt.pem`.
  - ``nats_key`` is the content of the file that can be found on the Satellite in the file :file:`/neteye/shared/nats-server/conf/certs/private/<tenant_name>-alyvix_metrics.key.pem`.
  - ``alyvix_node_hostname`` is the hostname of the Alyvix node that you need to configure.


**Multitenant - Tenant Shared**

- Configure a Tenant for each session by entering the Tenant name in the :ref:`alyvix-sessions-tab`.
  Furthermore use the :ref:`neteye-alyvix-node-setup` to automatically configure the NATS channels for the
  direct communication to the |ne| Master.

**Single Tenant - Direct to Master**

- Use the :ref:`neteye-alyvix-node-setup` command to automatically configure the NATS channels for the
  direct communication to the |ne| Master. Please note that in this case the Tenant related to all the
  sessions on the Alyvix node will be the Master Tenant.

.. _configure-metrics:

Step 3. Configure the retention of your metrics
```````````````````````````````````````````````

By default, the retention of the collected Test Cases performance metrics is of **365 days**.
If you would like to specify a different retention for a specific Tenant, please refer to the
:ref:`tenant configuration <tenants-configuration>`.

Step 4. Enjoy your metrics
``````````````````````````

On the |ne| Master, metrics generated during the run of Alyvix Session, for which NATS - InfluxDB connection
was configured, are stored in the `<tenant>-alyvix` InfluxDB database. You can now consult them directly
in InfluxDB or explore the data arranged in easy to read and meaningful dashboards via the
:ref:`itoa-module-description`.

Make sure that you choose the correct Grafana Organization associated to the Tenant
to which the performance metrics belong to.

.. topic:: Switching to a new Alyvix Performance metrics format

  Starting from version 2.1.0, Alyvix Service returns the performance metrics of the Test Cases running inside the same
  session as separate InfluxDB measurements, in contrast with the single measurement exposed in previous versions.

  The built-in dashboards available in the :ref:`itoa-module-description` are fully compatible with the new format.

  It is important to take into consideration that the Alyvix Test Cases Performance metrics collected with Alyvix Service
  2.1.0 or above will be stored in different InfluxDB measurements than those collected with previous versions.

  For this reason, we provide a script to migrate already collected Alyvix Performance metrics to the new format in the
  InfluxDB database dedicated to their Tenant. This will also allow their inclusion in the available built-in dashboards.
  Please note that the script **will not** delete the already collected
  metrics but will copy them in the correct measurements, ensuring that no data is loss during the migration process.

  To migrate the already collected metrics to the new measurements, after having performed the configuration outlined
  above, the following script is to be run:

  .. code:: bash

    bash /usr/share/neteye/scripts/alyvix/migrate_alyvix_influx_measurements.sh \
      "<source-database>" "<source-measurement>" "<target-tenant>"

  with the following parameters:

  - **source-database**: representing the database in InfluxDB where the previously collected metrics are stored
  - **source-measurement**: representing the measurement in the provided InfluxDB database where
    the previously collected metrics are stored
  - **target-tenant**: the Tenant to which specified metrics belong. They will be migrated to a separate measurement
    in the InfluxDB database dedicated to the Alyvix metrics for this Tenant.

  Moreover, in case the source InfluxDB node differs from the destination one,
  the script can be launched specifying four more parameters to define the
  connection to the source InfluxDB instance:

  .. code:: bash

    bash /usr/share/neteye/scripts/alyvix/migrate_alyvix_influx_measurements.sh \
      "<source-database>" "<source-measurement>" "<target-tenant>" \
      "<source-node-hostname>" "<source-node-port>" \
      "<source-node-admin-user>" "<source-node-admin-password>"

  where the new parameters are:

  - **source-node-hostname**: the hostname of the source InfluxDB instance
  - **source-node-port**: the port where InfluxDB is listening for connections on the source host
  - **source-node-admin-user**: username of a user with administrator privileges on the source InfluxDB instance
  - **source-node-admin-password**: password of the specified administrator user


  .. note:: The target InfluxDB node is inferred from the specified target Tenant, as configured in
            the :ref:`tenant configuration <tenants-configuration>`.
